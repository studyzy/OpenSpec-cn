## 1. Workspace 规划

- [ ] 1.1 确认共享的产品目标与尚未解决的范围问题。
- [ ] 1.2 识别受影响领域，适用时使用已注册的 workspace 链接名称。
- [ ] 1.3 在选定实现领域之前，评审 workspace 范围的 specs 与 design。

## 2. 受影响领域的实现

- [ ] 2.1 选定一个受影响领域，并在实现前确认其允许编辑的根目录。
- [ ] 2.2 仅在领域选定之后，才创建或更新仓库本地的实现制品。

## 3. 验证

- [ ] 3.1 验证 workspace 规划制品仍然是事实来源。
- [ ] 3.2 记录人工验收证据与后续修复项。
